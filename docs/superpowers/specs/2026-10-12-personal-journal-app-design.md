# 个人日志 App 首版设计规格

日期：2026-10-12  
状态：已通过产品设计评审  
技术方向：Flutter，首发 iPhone，Android 后续发布

## 1. 产品概述

本产品是一款个人自用、离线优先的日志记录 App。用户可以通过系统输入法的语音听写快速生成文字，同时添加图片和视频；所有内容按人物档案和日期自动归档。App 不在首版内提供 AI 分析，而是将选定范围的数据导出为 Markdown 分析资料包，传到 Windows 电脑后交给 ChatGPT、Claude、Codex 等工具分析。

首版不依赖账号、服务器或云数据库。用户拥有完整数据，可通过 ZIP 完整备份并恢复。iPhone 版本使用免费 Apple 账号侧载，不上架 App Store。

## 2. 产品目标

1. 用户打开 App 后能在 10 秒内完成一条文字记录。
2. 一条记录可以同时包含文字、多张图片和多个视频。
3. 图片和视频导入后不依赖系统相册原件。
4. 所有记录按人物档案和本地日期准确归档。
5. 用户可以生成适合电脑端 AI 阅读的 Markdown 资料包。
6. 用户可以生成可验证、可恢复的完整备份。
7. 无网络时所有核心功能正常工作。
8. 数据结构为未来 Android、云同步和 App 内 AI 分析保留扩展空间。

## 3. 首版范围

### 3.1 包含功能

- Flutter 跨平台代码库，第一阶段只构建和测试 iPhone。
- 首页常驻输入框。
- 使用 iOS 系统键盘语音听写，不保存原始录音。
- 输入内容自动保存为草稿，点击“保存”形成正式记录。
- 文字、图片、视频混合记录。
- 图片和视频复制到 App 私有目录。
- 视频自动生成缩略图。
- 多个本地人物档案及快速切换。
- 默认人物档案“我的日志”。
- 按人物、日期展示当天时间线。
- 日历查看历史记录。
- 查看、编辑和删除记录。
- 查看媒体存储占用。
- 按最近 7 天、本月、全部或自定义日期范围导出。
- 生成 AI 分析资料包。
- 创建完整备份。
- 从完整备份校验并合并恢复。
- 通过 iOS 系统分享菜单发送到微信或其他应用。
- 保存导出文件到 iPhone“文件”App。
- 免费 Apple 账号侧载所需的固定应用标识和刷新提醒。

### 3.2 明确不包含

- App 内录音和自建语音识别。
- 用户注册、登录和网络账号。
- 云数据库、实时同步和管理端。
- App 内调用大模型。
- ChatGPT 或 Claude 账号集成。
- 地理位置记录。
- 标签、复杂分类和全文搜索。
- 自动识别图片或视频内容。
- App 内 Face ID 锁。
- 自定义数据库或媒体文件加密。
- 多人协作和分享编辑。
- 推送通知。
- Android 正式发布。
- App Store 或 TestFlight 分发。

## 4. 人物档案

人物档案是本机上的独立数据空间，不是登录账号。

### 4.1 基本规则

- 首次启动自动创建“我的日志”，并设为当前档案。
- 用户可以创建其他档案，例如“孩子”。
- 首页顶部显示当前档案头像和名称，点击后打开档案切换器。
- 切换档案后，首页时间线、草稿、日历和普通导出立即限定为新档案。
- 每个档案维护独立草稿，切换档案不会丢失未提交内容。
- 有记录的档案默认只能归档隐藏，不能直接删除。
- 彻底删除档案前必须二次确认，并提示用户先创建完整备份。
- 完整备份始终包含全部档案，包括已归档档案。
- 普通分析导出默认选择当前档案，也允许手动选择多个档案。

### 4.2 数据结构

```text
Profile
├── id: UUID
├── name: String
├── avatarPath: String?
├── createdAt: DateTime
├── updatedAt: DateTime
├── isDefault: Bool
└── isArchived: Bool
```

未来接入服务器时，本地 `Profile.id` 保持不变，并增加服务端映射字段，不更换现有记录归属。

## 5. 信息架构与页面

App 使用四个底部入口。

### 5.1 今天

- 顶部显示当前人物档案切换器和当天日期。
- 输入框常驻首页。
- 输入框下方提供“图片”“视频”“保存”。
- 用户可在同一条记录中选择多个媒体文件。
- 下方按照创建时间倒序显示当天时间线。
- 点击记录进入详情；详情支持编辑和删除。

### 5.2 日历

- 月历标记有记录的日期。
- 点击日期显示当前档案在当天的全部记录。
- 切换月份不修改当前人物档案。

### 5.3 导出

分为两个入口：

1. 供 AI 分析：选择人物、日期范围和是否包含原始视频。
2. 完整备份：包含全部人物、数据库和全部媒体。

### 5.4 设置

- 管理人物档案。
- 展示数据库、图片、视频、缩略图和临时文件占用。
- 设置普通导出是否默认包含原始视频。
- 创建完整备份。
- 从完整备份恢复。
- 查看侧载签名提示和版本信息。

## 6. 记录与媒体数据模型

### 6.1 Entry

```text
Entry
├── id: UUID
├── profileId: UUID
├── text: String
├── createdAt: DateTime
├── updatedAt: DateTime
├── localDate: YYYY-MM-DD
├── timezoneOffsetMinutes: Int
└── status: draft | published
```

规则：

- `localDate` 在创建时固化，跨时区后不自动改变历史归档日期。
- 编辑记录不改变 `createdAt` 和 `localDate`。
- 文字、图片或视频至少存在一项，记录才能发布。
- 草稿按 `profileId` 隔离。

### 6.2 Media

```text
Media
├── id: UUID
├── entryId: UUID
├── type: image | video
├── relativePath: String
├── thumbnailPath: String?
├── originalFilename: String
├── mimeType: String
├── fileSize: Int64
├── width: Int?
├── height: Int?
├── durationMilliseconds: Int64?
├── caption: String?
├── checksumSha256: String
└── createdAt: DateTime
```

### 6.3 文件目录

```text
Application Support/
├── database/
│   └── journal.sqlite
├── media/
│   ├── images/
│   ├── videos/
│   └── thumbnails/
├── drafts/
└── temp/
```

数据库只保存相对路径，不保存设备绝对路径。

## 7. 保存、编辑与删除

### 7.1 草稿

- 输入变化经过短暂防抖后写入本地数据库。
- App 被系统终止后，下次启动恢复当前人物的草稿。
- 切换人物时，当前草稿保存，新人物显示自己的草稿。

### 7.2 媒体导入

1. 用户从系统相册或文件选择器选择媒体。
2. 文件复制到 App 临时目录。
3. 读取元数据、生成校验值和视频缩略图。
4. 数据库事务创建 `Entry` 与 `Media`。
5. 文件移动到正式私有目录。
6. 任一步骤失败时回滚数据库并清理临时文件。

### 7.3 删除

- 删除记录前显示二次确认。
- 确认后删除数据库记录及其关联媒体副本和缩略图。
- 删除失败时保留数据库关系并提示重试，避免产生不可恢复的悬空状态。

## 8. AI 分析资料包

### 8.1 导出选项

- 人物：当前人物、指定人物或多个人物。
- 日期：最近 7 天、本月、全部、自定义范围。
- 默认包含：Markdown、原始图片、视频缩略图、视频元数据和文字说明。
- 默认不包含：原始视频。
- 用户可以显式勾选原始视频。

### 8.2 包结构

```text
PersonalJournal-人物-日期范围.zip
├── README.md
├── profiles/
│   └── profile.json
├── days/
│   ├── 2026-10-11.md
│   └── 2026-10-12.md
├── media/
│   └── 2026-10-12/
│       ├── 092015-a3f2.jpg
│       ├── 201830-c927.mp4
│       └── 201830-c927-thumbnail.jpg
└── manifest.json
```

多人物导出时，在 `profiles/<profile-id>/` 下分别生成 `days` 和 `media`，避免同日内容混淆。

### 8.3 Markdown 格式

```markdown
# 2026年10月12日

人物：我的日志

## 09:20

今天确定了个人日志 App 的首版范围。

![产品草图](../media/2026-10-12/092015-a3f2.jpg)

## 20:18

晚上记录了一段训练视频。

[查看原始视频](../media/2026-10-12/201830-c927.mp4)

![视频预览](../media/2026-10-12/201830-c927-thumbnail.jpg)
```

图片使用相对路径嵌入。视频同时输出缩略图和相对链接；未勾选原始视频时，Markdown 只输出缩略图、说明、时长和“原视频未包含在本次导出”的标记。

### 8.4 分享

- ZIP 完成后调用 iOS 系统分享面板。
- 用户可以选择微信文件传输助手或其他已安装应用。
- 用户也可以选择“保存到文件”。
- 微信只是传输渠道，不视为可靠备份。

## 9. 完整备份与恢复

### 9.1 备份结构

```text
PersonalJournal-FullBackup-时间.zip
├── backup.sqlite
├── media/
│   ├── images/
│   ├── videos/
│   └── thumbnails/
├── manifest.json
└── checksums.json
```

`manifest.json` 包含：

- 应用版本；
- 数据库模式版本；
- 导出时间；
- 人物、记录及媒体数量；
- 文件格式版本。

`checksums.json` 保存数据库和全部媒体的 SHA-256，用于恢复前完整性检查。

### 9.2 恢复流程

1. 用户从“文件”选择完整备份 ZIP。
2. App 解压到临时目录。
3. 校验 ZIP 路径安全、格式版本和全部校验值。
4. 以只读方式打开备份数据库并校验模式。
5. 预览新增、重复、缺失和损坏的数据数量。
6. 用户确认后开始合并。
7. 相同 UUID 的人物、记录和媒体跳过，不覆盖本机数据。
8. 新文件先复制到临时目录，再在单个恢复事务中写入。
9. 失败时回滚数据库并删除本次新增文件。
10. 成功后清理临时目录并显示恢复报告。

恢复是幂等操作：同一备份重复导入不会生成重复数据。

## 11. 错误处理

- 空间不足：导入或导出前估算空间，阻止无法完成的操作。
- 媒体复制失败：保留文字和已成功媒体在草稿中，不创建损坏的正式记录。
- 缩略图失败：允许记录保存，但标记媒体待重试。
- 导出取消或中断：清理未完成的临时目录和 ZIP。
- 微信分享失败：保留已生成 ZIP，允许改为保存到“文件”。
- 数据库无法打开：进入只读故障界面，禁止继续写入，并提供诊断信息导出。
- 备份校验失败：不允许恢复，列出损坏或缺失文件。
- App 被强制关闭：下次启动恢复草稿并清理过期临时文件。

## 12. 隐私与安全

- 首版依赖 iPhone 系统锁屏和 iOS App 沙箱。
- 不申请位置、麦克风、联系人等非必要权限。
- 只在用户主动选择时申请照片或文件访问权限。
- 不上传任何日志、图片或视频。
- 不使用第三方分析 SDK 或广告 SDK。
- 导出文件离开 App 沙箱后由用户负责保管。
- App 不把 Apple 账号、侧载凭据或签名信息写入自身数据库。

## 13. 免费侧载与交付

### 13.1 约束

- 使用固定 Bundle ID，所有构建保持不变。
- iPhone 开启开发者模式。
- 使用普通 Apple 账号免费签名。
- 免费签名描述文件有效期为 7 天，必须定期刷新。
- 签名过期后 App 无法启动，但本地容器不会因过期自动删除。
- 卸载 App 会删除其本地容器，因此卸载前必须完整备份。

### 13.2 构建与安装流程

```text
Windows 编写和测试 Flutter 代码
→ macOS CI 生成 iOS 构建产物
→ Windows 下载 IPA
→ 使用本地侧载工具和个人 Apple 账号重新签名
→ 安装或刷新到已开启开发者模式的 iPhone
```

侧载工具不属于 App 功能，App 不集成侧载账号。应使用专门的 Apple 账号，禁止使用来源不明的共享证书。

### 13.3 App 内提醒

- 设置页记录用户手动确认的最近刷新日期。
- 根据该日期显示预计剩余天数，不声称读取苹果真实签名状态。
- 到期前两天显示本地提示。
- 刷新前提示创建完整备份。

首版不申请推送能力；提醒仅在 App 打开时显示，避免免费签名下引入额外权限和能力。

## 14. 测试策略

### 14.1 单元测试

- 人物切换与草稿隔离。
- 日期归档和时区固化。
- Markdown 转换和相对路径生成。
- 文件名清洗与中文、特殊字符处理。
- ZIP 清单和校验值生成。
- 恢复去重和模式版本判断。

### 14.2 集成测试

- SQLite 事务与媒体文件的一致性。
- 图片、视频复制及缩略图生成。
- 导出中断后的临时文件清理。
- 备份损坏、文件缺失和重复恢复。
- 数据库迁移。

### 14.3 真机验收

- 纯文字、纯图片、纯视频和混合记录。
- 系统语音听写输入。
- App 强制关闭后的草稿恢复。
- 跨午夜与跨时区记录。
- 大视频、低磁盘空间和分享取消。
- 微信分享与“文件”保存。
- ZIP 在 Windows 正确解压。
- Markdown 图片路径、视频链接和中文内容正确。
- 完整备份恢复到清空后的测试安装。
- 同一备份连续恢复两次无重复数据。
- 侧载刷新后原有数据仍可读取。

## 15. 验收标准

首版完成需同时满足：

1. 用户可在 10 秒内完成一条普通文字记录。
2. 记录至少支持 10 张图片与 1 个视频的组合，不丢失媒体关系。
3. 清理系统相册原件后，App 内已导入媒体仍可查看。
4. 强制关闭 App 后草稿能够恢复。
5. 人物切换后不显示其他人物的记录或草稿。
6. 一个月的数据可生成有效分析 ZIP。
7. 分析 ZIP 在 Windows 解压后，Markdown 与媒体相对路径有效。
8. 完整备份通过校验并可合并恢复。
9. 重复恢复不会产生重复记录。
10. 核心功能在飞行模式下正常工作。
11. 免费签名刷新安装后，本地数据保持不变。

## 16. 后续阶段

按照优先级规划：

1. Android 真机适配和 APK 发布。
2. 本地全文搜索、标签和人物关联。
3. 可选端到端加密同步服务和管理端。
4. App 内 AI 日报、周报与个人数据问答。
5. Face ID 和导出包密码保护。

未来 AI 能力必须建立在用户明确选择的数据范围上，模型输出与原始记录分开存储，不允许模型自动修改或删除原始记录。
